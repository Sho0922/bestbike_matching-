# 非機能要件・技術方針 — BestBike × 教習所マッチング

版数 v1.0 ／ 2026-08-04

---

## 1. 技術スタック

### 1.1 選定

| レイヤ | 採用 | 理由 |
|---|---|---|
| フロント / サーバ | **Next.js 15（App Router）+ TypeScript** | SSR による SEO（教習所詳細ページは検索流入が生命線）。API を別サーバに分けず1リポジトリで完結 |
| スタイル | **Tailwind CSS** | プロトタイプが Tailwind で書かれており、そのまま資産になる |
| DB / 認証 / ストレージ | **Supabase（PostgreSQL 15）** | Postgres の RLS を最終防衛線に使える。認証・ストレージ込みでインフラ構築を圧縮 |
| ホスティング | **Vercel** | Next.js との親和性。プレビュー環境が PR ごとに自動生成される |
| メール | **Resend** | React Email でテンプレートを型安全に書ける。月3,000通まで無料 |
| 地図 | **Google Maps JavaScript API** | 日本の住所・駅データの精度。MapLibre + 国土地理院タイルは代替案 |
| 監視 | **Sentry** ＋ Vercel Analytics | エラー追跡。無料枠で開始可 |
| CI | **GitHub Actions** | lint / typecheck / test / build をPRごとに実行 |
| E2E | **Playwright** | 主要導線の回帰を自動化 |

### 1.2 この構成にした理由

1. **API サーバを分けない**。ユーザー数が数万規模までは Next.js の Route Handlers で足りる。
   分けた瞬間に、デプロイ・認証・型の同期という3つの継続コストが発生する。
2. **RLS を持つ DB を選ぶ**。このシステムは「他校の申込者情報が漏れない」ことが生命線であり、
   アプリ層の実装ミスがそのまま漏洩にならない構造が要る（§2.2）。
3. **プロトタイプの資産を捨てない**。Tailwind クラスをそのまま移植でき、
   デザイン工程を丸ごと圧縮できる。

### 1.3 地図の選定

| 案 | 費用 | 精度 | 判断 |
|---|---|---|---|
| Google Maps JS API | $7/1,000ロード（月$200無料枠） | ◎ | **採用**。月28,000ロードまで実質無料 |
| MapLibre GL + 国土地理院タイル | 無料 | ○ | 予算制約が強い場合の代替 |
| 静的地図画像 | ほぼ無料 | △ | ピンのクリック導線が作れず、UXが落ちる |

## 2. セキュリティ

### 2.1 【最重要】特典情報をクライアントに漏らさない

マイページの特典カードは `status = 'confirmed'` のときだけ表示される。
この出し分けを **CSS や条件付きレンダリングだけで実装してはならない**。

| 層 | 実装 | 役割 |
|---|---|---|
| 表示層 | `{status === 'confirmed' && <BenefitCard/>}` | UX |
| **API層** | `confirmed` 以外は `benefit` キーをレスポンスに**含めない** | **防御** |
| **DB層（RLS）** | `benefits` は `user_id = auth.uid() AND status = 'active'` のみ返す | **最終防衛線** |

未確定の申込に対してAPIがクーポンコードを返してしまうと、
DevTools のネットワークタブを開くだけで、入会せずに永年10%OFF が手に入る。
`03_data-model.md` §4.2 の RLS ポリシーは、この事故を防ぐために存在する。

### 2.2 教習所間のデータ分離

| 脅威 | 対策 |
|---|---|
| A校のスタッフがB校の申込を閲覧 | RLS `is_staff_of(school_id)` ＋ アプリ層の所属チェック（二重） |
| ID列挙による探索 | 主キーを `uuid`（連番でない）にする。権限外は **404**（403でない） |
| 教習所がクーポンコードを取得 | `benefits` に `school_staff` の SELECT ポリシーを作らない。確定APIのレスポンスにもコードを含めない |

### 2.3 金銭操作の保護

| 対策 | 内容 |
|---|---|
| MFA 必須 | `school_staff` / `platform_admin` はログイン時にTOTP必須。入会確定・確定取消は MFA 済セッションのみ |
| 冪等性 | `Idempotency-Key` 必須。24時間保持 |
| 行ロック | `SELECT ... FOR UPDATE` で並行リクエストを直列化 |
| DB制約 | `UNIQUE(application_id)` on `referral_fees` / `benefits` |
| 監査ログ | 操作者・IP・UA・前後状態。`UPDATE`/`DELETE` をDBロールから剥奪 |
| 権限分離 | `school_staff.can_confirm` で、確定操作を特定の担当者のみに絞れる |
| 確認ダイアログ | 金額と不可逆性を明示（`02_screen-spec.md` §3.7.3） |

### 2.4 一般的な脅威への対応

| # | 脅威 | 対策 |
|---|---|---|
| S-1 | SQLインジェクション | ORM / パラメータ化クエリのみ。文字列連結SQLを禁止（CIでlint） |
| S-2 | XSS | React の自動エスケープ。`dangerouslySetInnerHTML` を全面禁止（ESLintで機械的に検出） |
| S-3 | CSRF | SameSite=Lax Cookie ＋ Origin ヘッダ検証 |
| S-4 | 認証情報の漏洩 | パスワードは Supabase Auth（bcrypt）。自前実装しない |
| S-5 | 総当たり | 認証エンドポイントに 10req/分/IP のレート制限。5回失敗で15分ロック |
| S-6 | 個人情報の過剰露出 | APIレスポンスは必要な列のみ。`SELECT *` をそのまま返さない |
| S-7 | シークレットの混入 | `.env` を gitignore。GitHub Secret Scanning ＋ `gitleaks` を CI に組み込む |
| S-8 | 依存の脆弱性 | Dependabot ＋ `npm audit` を CI で実行。high 以上でPRをブロック |
| S-9 | 管理画面の露出 | `/admin` `/school` を `X-Robots-Tag: noindex`。IP制限は運用次第で追加 |
| S-10 | ログへの個人情報混入 | 構造化ログでメール・電話・氏名をマスクするフィルタを必須化 |

### 2.5 データ保護

| 項目 | 方針 |
|---|---|
| 通信 | TLS 1.2以上のみ。HSTS 有効 |
| 保管 | Supabase のディスク暗号化（AES-256） |
| バックアップ | 日次自動 + PITR（7日間）。四半期に1度、復旧演習を実施する |
| 保持期間 | 申込データは確定/終了から**5年**（会計・紛争対応）。以降は個人情報を匿名化し統計のみ保持 |
| 削除請求 | 個人情報保護法に基づく削除請求に対応。`users` の個人情報列を匿名化し、`applications` は統計用に残す |

## 3. 事業リスクへのシステム対応

### 3.1 【最大の事業リスク】中抜き（確定漏れ）

このビジネスモデルの構造的な弱点は、**紹介料の発生が教習所の自発的な操作に依存している**ことにある。
教習所は「入会確定」を押さなければ ¥5,000 を払わずに済む。悪意がなくても、押し忘れは必ず起きる。

**対策（システムで検知する）**

| # | 施策 | 実装 |
|---|---|---|
| L-1 | **入校予定日 超過アラート** | `scheduled_start_date` を7日過ぎても `confirmed` にならない申込を、運営ダッシュボードに一覧表示 |
| L-2 | **ユーザー側の申告導線** | マイページに「通い始めましたか？」を表示。ユーザーが「はい」を押すと運営にフラグが立つ |
| L-3 | **長期未処理アラート** | `submitted` のまま5営業日を超えた申込を教習所へリマインド（自動メール） |
| L-4 | **成約率の異常検知** | 校ごとの `confirmed / submitted` 比率が全体平均を大きく下回る校を月次で抽出 |
| L-5 | 契約による裏付け | 提携契約書に「本プラットフォーム経由の申込者が入校した場合、確定操作を行う」義務を明記 |

> L-1・L-2 は Phase 1 に入れる価値がある。**売上の取りこぼしを検知できない状態で
> スケールさせると、成長するほど損失が拡大する。**

### 3.2 二重計上

§2.3 の三重防御（冪等キー・行ロック・UNIQUE制約）で対応。詳細は `04_api-spec.md` §4.3。

### 3.3 教習所の情報鮮度

料金・空き枠が実態とズレると、ユーザーの信頼とともに景表法リスクが発生する。

| 施策 | Phase |
|---|---|
| 掲載情報に「最終更新日」を表示 | 1 |
| 90日更新のない校を運営ダッシュボードで警告 | 2 |
| 教習所によるセルフ更新画面 | 2 |

## 4. 性能

### 4.1 目標値

| 指標 | 目標 | 測定 |
|---|---|---|
| LCP（教習所一覧・詳細） | 2.5秒以内（モバイル4G） | Lighthouse CI |
| INP | 200ms以内 | Vercel Analytics |
| API レスポンス（p95） | 検索 500ms / その他 300ms | Sentry Performance |
| 入会確定API（p95） | 1秒以内 | 同上 |
| 同時接続 | 500 | 負荷試験 |

### 4.2 想定規模（1年目）

| 指標 | 想定 |
|---|---|
| 提携教習所 | 24校 → 100校 |
| 月間申込 | 100件 → 500件 |
| 月間UU | 5,000 → 30,000 |
| DB総レコード | 10万件未満 |

この規模では Supabase の Small インスタンスで十分。
チューニングより、**インデックス設計（`03_data-model.md` §3）を守ること**が効く。

### 4.3 施策

| # | 施策 |
|---|---|
| P-1 | 教習所一覧・詳細は ISR（60秒）でキャッシュ。掲載情報の更新時にオンデマンド再検証 |
| P-2 | 画像は `next/image` で WebP 配信・遅延読み込み |
| P-3 | 地図は初期表示ではリスト優先とし、地図ライブラリを動的import |
| P-4 | 検索クエリは複合インデックス（`status`, `prefecture`, `city`）で捌く |
| P-5 | ダッシュボードの集計は materialized view を日次更新（Phase 2、件数増加時） |

## 5. 法令・コンプライアンス

### 5.1 個人情報保護法

| # | 論点 | 対応 |
|---|---|---|
| C-1 | **第三者提供（第27条）** | 申込フォームで、当該教習所への提供に対する**個別の同意**を取得し、`consents` に版数・日時・IP とともに記録する（`02_screen-spec.md` §3.4） |
| C-2 | 利用目的の特定・通知 | プライバシーポリシーに「提携教習所への提供」を明記 |
| C-3 | 安全管理措置 | §2 のとおり |
| C-4 | 開示・訂正・利用停止請求 | 問い合わせ窓口を設置し、30日以内に対応する運用を定める |
| C-5 | 委託先の監督 | Supabase / Vercel / Resend を委託先として台帳管理 |

> **C-1 はプロトタイプに不足している**。同意チェックが2件（教習所規約・プライバシーポリシー）
> しかなく、第三者提供の同意が独立して取得されていない。実装時に必ず追加する。

### 5.2 景品表示法

| # | 表示 | リスク | 対応 |
|---|---|---|---|
| C-6 | 「永年10%OFF」 | 将来終了すると有利誤認 | 規約に変更・終了条件を明記し、画面から規約へリンクする |
| C-7 | 「最短2週間」 | 実現困難なら優良誤認 | 教習所からの申告を根拠資料として保存。「※混雑状況により変動」を併記 |
| C-8 | 「BestBike推薦」 | 選定基準が不明確 | 推薦基準を公開ページで開示する |
| C-9 | 「立ちゴケ安心制度」 | **内容未確定**（確認事項D） | 内容が確定するまでLPに表示しない |
| C-10 | 価格表示 | 総額表示義務 | すべて税込表示。追加費用（教材費・検定料等）の有無を明記 |

### 5.3 その他

| # | 論点 | 対応 |
|---|---|---|
| C-11 | **資金決済法** | 教習料金は本プラットフォームで収受しない（`01_requirements.md` BR-9）。将来決済を持つ場合は、収納代行 or 資金移動業の整理を先に行う |
| C-12 | 特定商取引法 | 本プラットフォームは仲介。事業者情報・連絡先・キャンセルポリシーを表示 |
| C-13 | **インボイス制度** | 紹介料の請求書は適格請求書の要件（登録番号・税率区分・税額）を満たす（Phase 2） |
| C-14 | 電子帳簿保存法 | 請求書データは検索要件（日付・金額・取引先）を満たして保存 |
| C-15 | 特定電子メール法 | 通知メールに送信者情報・配信停止導線を記載。取引メールと広告メールを分離 |
| C-16 | 道路交通法 | 受講可能年齢（普通二輪16歳／大型二輪18歳）をシステムで検証（`04_api-spec.md` §3.1） |

## 6. 可用性・運用

| 項目 | 方針 |
|---|---|
| 目標稼働率 | 99.5%（月間ダウンタイム 3.6時間以内） |
| デプロイ | Vercel の自動デプロイ。PRごとにプレビュー環境 |
| ロールバック | Vercel の即時ロールバック。DBマイグレーションは前方互換を保つ |
| 障害検知 | Sentry のアラート → Slack。5xx率 1%超で通知 |
| 定期監視 | Outbox の `dead` レコード発生時に即アラート（特典が発行されていない可能性） |
| ログ | Vercel Logs（30日）＋ Sentry。個人情報はマスク |
| バックアップ | 日次 + PITR 7日 |

| # | 条件 | 重要度 | 通知先 |
|---|---|---|---|
| OP-1 | `outbox_events.status = 'dead'` が発生 | **高** | 運営 Slack 即時 |
| OP-2 | 入会確定APIの 5xx | **高** | 即時 |
| OP-3 | `scheduled_start_date` 超過7日の未確定申込 | 中 | 日次サマリ |
| OP-4 | `submitted` のまま5営業日超 | 中 | 日次サマリ |

## 7. 環境

| 環境 | 用途 | DB | 備考 |
|---|---|---|---|
| local | 開発 | Supabase local（Docker） | シードデータ投入 |
| preview | PRレビュー | Supabase ブランチDB | PRごとに自動生成 |
| staging | 受入テスト | 専用プロジェクト | 本番同等。**本番データを入れない** |
| production | 本番 | 専用プロジェクト | |

### 7.1 環境変数

| 変数 | 用途 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase エンドポイント |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | クライアント用（RLS前提） |
| `SUPABASE_SERVICE_ROLE_KEY` | **サーバ専用**。クライアントに絶対に露出させない |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | 地図。リファラ制限を必ず設定 |
| `RESEND_API_KEY` | メール送信 |
| `BESTBIKE_WEBHOOK_SECRET` | 本体連携のHMAC共有鍵 |
| `SENTRY_DSN` | エラー監視 |

> `SUPABASE_SERVICE_ROLE_KEY` は RLS を貫通する。
> `NEXT_PUBLIC_` プレフィックスを付けないこと、
> Server Component / Route Handler 以外から参照しないことを、レビューで必ず確認する。

## 8. コード品質

| # | 基準 |
|---|---|
| Q-1 | TypeScript `strict: true`。`any` の使用はレビューで都度承認 |
| Q-2 | ESLint（`next/core-web-vitals` + `@typescript-eslint`）＋ Prettier。CIで強制 |
| Q-3 | 1チケット1PR。差分は原則500行以内 |
| Q-4 | 金銭に関わるロジック（確定・紹介料・特典）は**テスト必須**。カバレッジ目標80%以上 |
| Q-5 | DBアクセスは `lib/db/` に集約。コンポーネントから直接クエリを書かない |
| Q-6 | APIの入力検証は Zod スキーマを唯一の定義とし、型もそこから導出する |
| Q-7 | マジックナンバー禁止。`5000` は `schools.referral_fee_amount`、`10` は `benefit_masters.discount_rate` から取る |
