## この設計で最も重要な1点

> **収益は「入会確定」という1つのイベントに集約される。**
> **この1点の正確性・不可逆性・検証可能性を守ることが、このシステムの設計の全て。**

教習所の担当者が管理画面で「入会確定」ボタンを押す。
この操作ひとつで、¥5,000 の紹介料が計上され、ユーザーに永年10%OFF が発行される。
それ以外の場所でお金は一切動かない。

だからこの1点に、3つの防御を重ねている。

| 層 | 実装 | 防ぐもの |
|---|---|---|
| **冪等性** | `Idempotency-Key` ＋ `SELECT ... FOR UPDATE` ＋ `UNIQUE(application_id)` | 連打・リトライ・並行リクエストによる**二重計上** |
| **監査** | `confirmed_by` ＋ `audit_logs`（UPDATE/DELETE を DBロールから剥奪） | 「誰がいつ押したか分からない」状態。取消は運営のみ |
| **突合** | 入校予定日の超過アラート ＋ ユーザー側の申告導線 | 押し忘れ・意図的な未操作による**中抜き** |

関連：[03 §3.8](03_data-model.md)、[04 §4.3](04_api-spec.md)、[06 T-10](06_dev-instructions-codex.md)、[07 §5](07_test-plan.md)

### なぜ「三重」なのか

二重計上はアプリのバグでは済まない。
教習所に「押していない ¥5,000」を請求した瞬間、提携関係が壊れる。

逆に、押し忘れを検知できなければ、送客しても売上が立たない。
提携が10校のうちは目視で追えるが、100校になったら追えない。
**成長するほど損失が拡大する構造**になっている。

このシステムで技術的に最も難しいのは検索でも地図でもなく、
この1つのボタンを正しく作ることにある。

## リポジトリ構成

```

prototype/index.html  クライアント提示用プロトタイプ（ビルド不要・単体で開ける）
src/                  プロトタイプのReactソース（npm start で起動）
```

### プロトタイプの起動

```bash
# ビルド不要（推奨・クライアント提示用）
open prototype/index.html

# React版
npm install && npm start
```
