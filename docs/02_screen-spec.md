**バリデーション**

| タイミング | 動作 |
|---|---|
| blur時 | 項目単位でエラー表示 |

- AC-F-2: 同意3件すべてにチェックがなければ送信ボタンが無効

- AC-F-4: 二重送信（連打）で申込が2件作られない
- AC-F-5: 同一ユーザー×同一教習所の未完了申込があるとき、重複エラーを返す
- AC-F-6: 送信中はボタンをローディング状態にし、再クリックを受け付けない

#### 3.7.3 ⚡ 入会確定フロー（最重要）

```mermaid
sequenceDiagram
  actor SS as 教習所スタッフ
  participant UI as 管理画面
  participant API as 確定API
  participant DB as DB

  SS->>UI: 「入会確定」クリック
  UI->>SS: 確認ダイアログ<br/>「紹介料¥5,000が計上されます。取消には運営への連絡が必要です」
  SS->>UI: 「確定する」
  UI->>API: POST /confirm<br/>Idempotency-Key: {uuid}
  API->>DB: BEGIN
  API->>DB: SELECT ... FOR UPDATE（行ロック）
  alt すでに confirmed
    API-->>UI: 200（初回結果を返す・二重計上しない）
  else scheduled
    API->>DB: applications.status = confirmed
    API->>DB: INSERT referral_fees (¥5,000)
    API->>DB: INSERT benefits (10%OFF)
    API->>DB: INSERT audit_logs
    API->>DB: COMMIT
    API-->>UI: 200 + 発行コード
  else status が scheduled でない
    API-->>UI: 409 Conflict
  end
```

**確認ダイアログの必須文言**

> この申込を「入会確定」にします。
> - BestBikeへの紹介料 **¥5,000** が計上されます
> - 申込者に **BestBike永年10%OFFコード** が自動発行されます
> - **確定後の取消しには、BestBike運営への連絡が必要です**

**受入基準**

- AC-SA-1: 自校の申込のみが一覧・詳細・APIすべてで取得できる
- AC-SA-2: 他校の `application_id` を直接指定しても404
- AC-SA-3: 「入会確定」は確認ダイアログを必ず経由する
- AC-SA-4: 連打・再送で紹介料が2件計上されない
- AC-SA-5: `scheduled` 以外のステータスから確定できない（`01_requirements.md` BR-4）
- AC-SA-6: 確定後、教習所側UIに取消ボタンが存在しない
- AC-SA-7: 操作者・IP・日時が `audit_logs` に残る

## 5. アクセシビリティ要件
